# API Agent Playbook

Focus: Express server in `packages/api/` that exposes read-only endpoints backed by the SQLite database generated by the ETL.

## Core Responsibilities

- Keep the Express server aligned with the schema in `bancoDados/monitordespesas/monitordespesas.db`.
- Extend or fix services under `packages/api/src/services/` without breaking existing filters.
- Ensure query normalization stays in sync with shared types from `@a-republica/shared`.
- Coordinate with the ETL agent if table layouts or column names change.

## Key Paths

- `packages/api/src/server.ts` - Express bootstrap.
- `packages/api/src/routes/` - route definitions.
- `packages/api/src/services/fornecedores-service.ts` - main supplier queries.
- `packages/api/src/db/` - `openReadOnlyDatabase` helpers and error wrappers.
- `.env.example` - expected environment variables (`SQLITE_DB_PATH`, etc.).

## Command Checklist (PowerShell)

```pwsh
cd packages/api
pnpm install                       # only if deps changed
pnpm type-check
pnpm lint
pnpm test                          # add coverage when available
pnpm build
pnpm dev                           # when you need to exercise endpoints
```

To point at a fresh ETL output, update `.env`:

```
SQLITE_DB_PATH=../../bancoDados/monitordespesas/monitordespesas.db
```

Smoke test the main endpoints while `pnpm dev` is running:

```pwsh
curl http://localhost:3900/fornecedores?perPage=5
curl http://localhost:3900/fornecedores/stats
curl http://localhost:3900/health
```

## Validation Steps

1. Run `pnpm dev` and hit critical routes such as `/fornecedores`, `/fornecedores/stats`.
2. Compare totals from the API with `manifest.json` or direct SQLite queries.
3. Run targeted SQL via `sqlite3` to confirm indexes:

```pwsh
sqlite3 ..\..\bancoDados\monitordespesas\monitordespesas.db "SELECT name FROM sqlite_master WHERE type='index';"
```
4. Ensure responses respect pagination, ordering, and filtering; adjust unit tests as needed.
5. Document any schema assumptions in this guide and in `ESTADO-ATUAL-PROJETO.md`.

## Guardrails

- Do not mutate the database from the API; all endpoints are read-only.
- Avoid raw string concatenation in SQL; use parameter binding like the existing services.
- Keep the API returning deterministic fields; never inject mock data to pad responses.
- Coordinate version bumps to shared types with the frontend agent to prevent breaking changes.

## Handoff Notes

Summaries must include:
- Routes touched and new query params or response fields.
- Test commands and outcomes.
- Any dependency on specific ETL builds (include manifest timestamp/hash).
- Suggested verification steps for frontend consumers.
